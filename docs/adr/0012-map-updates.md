# 12. Map updates: keeping tracked maps current from their GitHub Releases

Status: accepted (2026-10-31). Issues 30 (spec) and 31 (check, download and the Maps section); 32 (Auto-host uses the newest installed version) builds on it. Follows ADR 0009's network rule.

## Context

Popular custom maps such as Legion TD Team OZE ship hotfixes every week or two. Players end up on old versions without noticing, a host on the wrong version recently had a match end early, and lobbies then force slow map downloads (about 200 KB/s on macOS). Team OZE publishes every version as an official GitHub Release of `team-oze/Legion-TD` (no licence: download for play only, never redistribute), with one `.w3x` asset and the SHA-256 digest GitHub computes for it. Installed copies sit in `<Maps folder>/Download/` under names that vary: `Legion_TD_11.4c-hf5_Team_OZE.w3x`, `Legion_TD_11.2c-hf1_TeamOZE.w3x`, `Legion_TD_6.2b_Team_OZE (1).w3x`. Older sources are unusable: `Team-OZE/LegionTD-Map` is archived at v5.0, and the w3reforged page lags behind with no API or checksum.

## Decision

- **Tracked maps** are a `[[maps.tracked]]` list in `config.toml`: a name for the window, the `owner/name` repository, a regular expression the whole file name must match with a group named `version`, and the Maps subfolder downloads go into (`Download`). Legion TD Team OZE is the first. The container refuses a pattern without a `version` group, a repository that isn't `owner/name`, and a folder that isn't inside the Maps folder (`filepath.IsLocal`). Only maps with an official GitHub release feed are tracked; nothing scrapes other sites.
- **Port.** `contract.MapReleases`: `Latest(ctx, tracked)` returns the newest release (`dto.MapRelease`: tag, version from the asset's name, asset name, size, SHA-256, download URL, release page); `Download(ctx, release, dir, progress)` returns the placed file's path. Errors the player can act on implement `contract.UpdateProblem`; GitHub's rate limit implements `contract.RetryLater`, as for app updates.
- **Network rule** (same as ADR 0009, `infrastructure/mapreleases`): plain GETs to `api.github.com` (`/repos/{repo}/releases/latest`, which skips drafts and pre-releases; both are checked again) and the release hosts it links (`github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`), over HTTPS only, redirects included (`updater.NewClient`). Requests carry GitHub's `Accept`, `X-GitHub-Api-Version` and the `wc3-team-follow` User-Agent, nothing else: no token, cookie, BattleTag, game data or identifier. The API base must be `https` (the container refuses anything else); an asset or page link elsewhere is dropped. Each request times out after `[maps] timeout`; a download has no overall limit but gives up when nothing arrives for that long.
- **Checksum.** The asset is the first one whose name matches the map's pattern. A release whose matching asset has no `sha256:` digest of 64 hex characters is refused with a sentence; nothing is downloaded without a published checksum.
- **File rules** (`Download`):
  - The asset name must match the pattern with the release's version, be a bare file name (no `/`, `\`, `..`) and end in `.w3x` or `.w3m`; the URL must pass the network rule; the listed size must be under `[maps] max_size_mb` (256 MB). Each is checked before any request.
  - The file streams into a temporary file `.wc3-team-follow-map-*.part` in the target folder (hidden from the map browser, ignored by the game), hashed as it arrives and capped at the size limit. Only on a SHA-256 match is it linked into place under the asset's name; on any error, a cancel included, the temporary file is removed. Leftovers from an interrupted run (only this prefix) are removed before the next download.
  - **Never overwrite:** the final name is placed with a hard link, which fails if a file exists; where links aren't supported, it checks the name is free and renames. An existing file of the same name is left as it is, and the row says so.
  - **Never delete:** old versions stay, so the player can still join lobbies hosted on them. Team Follow only ever removes its own temporary files.
  - **No redistribution:** the file is downloaded from the publisher's own release for this player's play, kept in their Maps folder, and never uploaded, shared or served anywhere.
- **Installed?** `MapLibrary.Installed(ctx, root, tracked)` walks the Maps folder (the chosen one, or the detected one), skipping hidden files and folders within the map search's 3-second budget, and returns every file matching the pattern with its version and time, most recently changed first. The newest release counts as installed when one of them has the same version, compared as strings ignoring case; there is no version ordering, so a re-upload of the same version isn't fetched again. #32 reuses this lookup for "the newest installed version".
- **Planner** (`domain/mapupdate`, pure, driven by the companion with its clock). Checks run at start-up and every `[maps] check_interval` (6 h) while **Keep maps up to date** is on (`mapUpdates`, on by default, saved in `friends.json` only when off). A failed check or download is retried after `retry_interval` (30 min), or once GitHub's rate limit lifts. A failed automatic check is quiet and keeps what was found before; a refused release (no checksum) is always shown. **Check now** works with the switch off but never downloads then; the row says the newer version is out and to turn the switch on. Turning the switch on checks at once; turning it off stops a running download (nothing kept). One check at a time; maps are checked and downloaded one after another.
- **States per map:** `idle`, `checking`, `upToDate`, `missing` (newer version, switch off), `downloading` (bytes done and total), `done` ("Legion TD 11.4c-hf9 is ready in your Maps folder."), `failed` (why, as a sentence). Activity gets "Downloading Legion TD 11.4c-hf9 into your Maps folder.", the ready line, or the failure.
- **Window.** A Maps section under Updates: one row per tracked map with its installed and newest versions, a state badge, the progress bar and "Downloading Legion TD 11.4c-hf9… 12 of 30 MB" while downloading, the completion or failure sentence, Release page, Check now and the switch. Everything is plain text set with `textContent`. The bridge's `OpenMapReleasePage(name)` opens only the `https://github.com/` page from the companion's state for that map, never an address from the page.
- **Logging.** `maps.check` (map, latest version, installed count, whether it downloads), `maps.check_failed`, `maps.installed`, `maps.download_start` (bytes), `maps.downloaded`, `maps.download_done` (path), `maps.download_failed`, `maps.download_cancelled`, `maps.checksum_mismatch`. Nothing personal is involved.

## Addendum: the newest installed version (issue 32, 2026-10-31)

Auto-host's **Use the newest installed version** needs an order the "Installed?" rule above doesn't: the newest installed file of a tracked map is the one with the highest version (`mapupdate.Newest`, `mapupdate.CompareVersions`: runs of digits compared as numbers, the rest as text ignoring case, a prefix first), and of equal versions the most recently changed. The time a file changed doesn't decide, because the game itself downloads old versions into `Maps/Download` when the player joins a lobby hosted on one. The Maps section's installed column uses the same order when the newest release isn't installed. "Already have it" stays a string comparison, as above. The companion works the file out before each lobby; the follow engine waits for it and never reads files (see `docs/follow-behaviour.md`, Auto-host).

## Consequences

- Team Follow makes a few more HTTPS requests to GitHub per day (one per tracked map per check), sharing the 60-per-hour unauthenticated limit with app update checks; the retry rule respects it.
- Maps download in the background without a click while the switch is on (30 MB for Legion TD), into the Maps folder only. Players who don't want that turn it off.
- The Maps folder grows by one file per version; Team Follow never cleans it up.
- The integrity check is GitHub's own digest of the asset; a release whose file and digest were both replaced by the publisher would pass, as with app updates.
- Adding a map is a config change plus a live check of its release names; maps without official GitHub releases stay out of scope.
